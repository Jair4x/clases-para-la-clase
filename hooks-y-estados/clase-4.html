useContext y custom hooks

Cómo evitar pasar props de más, y cómo armar tus propios hooks reutilizables

1El problema: prop drilling

Con lo visto hasta ahora, si un dato (por ejemplo, el usuario logueado) lo necesita un componente que está varios niveles adentro del árbol, hay que pasarlo por props a través de todos los componentes intermedios, aunque no lo usen:

App.jsx
function App() {
  const usuario = { nombre: 'Ana' };
  return <Layout usuario={usuario} />;
}

function Layout({ usuario }) {
  return <Sidebar usuario={usuario} />; // Layout no usa "usuario", solo lo reenvía
}

function Sidebar({ usuario }) {
  return <InsigniaUsuario usuario={usuario} />; // tampoco lo usa acá
}

function InsigniaUsuario({ usuario }) {
  return <p>Hola, {usuario.nombre}</p>; // acá sí se usa, 3 niveles después
}

A esto se le llama prop drilling (algo así como "perforar props" o "taladrar props" hasta el fondo, para hacerlas llegar): Layout y Sidebar reciben y reenvían usuario sin necesitarlo, solo porque están en el medio del camino.

Por qué es un problema No es que el código no funcione, funciona perfectamente. El problema es de mantenimiento: Layout y Sidebar terminan atados a un dato que ni les interesa, solo porque alguien más abajo lo necesita. Si mañana InsigniaUsuario también necesita, por ejemplo, el idioma, hay que volver a agregar esa prop en cada componente intermedio. Y si se renombra usuario, hay que tocar los cuatro archivos, no uno. Cuantos más niveles, peor: componentes que deberían ser genéricos y reutilizables (como Layout) terminan atados a datos muy específicos de la aplicación.

2Context: un dato compartido

Context es una forma de declarar un valor que está disponible para toda una parte del árbol de componentes, sin tener que pasarlo manualmente nivel por nivel. Es como el wifi de una casa: el router "transmite la señal" en una zona, y cualquier dispositivo que esté dentro de esa zona se conecta directo, sin que haga falta tender un cable hasta cada dispositivo uno por uno.

Armar y usar un Context tiene tres partes:

  • Crear el Context, con createContext. Esto da un objeto que sirve como "canal" de comunicación.
  • Proveer un valor, envolviendo una parte del árbol con el Provider de ese Context, y diciéndole qué valor transmitir.
  • Leer el valor, desde cualquier componente adentro de ese Provider, sin importar a cuántos niveles de distancia esté (esto se hace con useContext, en la próxima sección).

1. Crear el Context

UsuarioContext.js
import { createContext } from 'react';

export const UsuarioContext = createContext(null);

createContext(null) crea el "canal". El null es un valor por defecto, que solo se usaría si alguien intenta leer el Context desde afuera de cualquier Provider; en la práctica, casi siempre va a haber un Provider de por medio.

2. Proveer un valor con el Provider

Todo Context que se crea con createContext trae incorporado un componente Provider (literalmente, "el que provee"). Es un componente que envuelve una parte del árbol, y le pasa a todo lo que esté adentro el valor indicado en su prop value, sin que ese valor tenga que reaparecer como prop en cada nivel intermedio:

App.jsx
import { UsuarioContext } from './UsuarioContext';

function App() {
  const usuario = { nombre: 'Ana' };

  return (
    <UsuarioContext.Provider value={usuario}>
      <Layout />
    </UsuarioContext.Provider>
  );
}

3useContext: leer el valor

Cualquier componente adentro del Provider, sin importar a cuántos niveles de distancia esté, puede leer el valor con useContext:

InsigniaUsuario.jsx
import { useContext } from 'react';
import { UsuarioContext } from './UsuarioContext';

function InsigniaUsuario() {
  const usuario = useContext(UsuarioContext);
  return <p>Hola, {usuario.nombre}</p>;
}

Layout y Sidebar desaparecen del problema: ya no reciben ni reenvían usuario, porque nunca lo necesitaron.

Cuándo usarlo (y cuándo no) Context sirve para datos realmente globales: usuario logueado, tema claro/oscuro, idioma. No es para reemplazar todas las props; si dos componentes están cerca en el árbol, pasar una prop directamente sigue siendo más simple y explícito.

4Hooks propios: por qué y para qué

Un hook propio es simplemente una función que empieza con use y que por dentro usa uno o más hooks de React. Sirve para reutilizar lógica con estado entre distintos componentes, sin repetir código.

useTema.js
import { useContext } from 'react';
import { TemaContext } from './TemaContext';

export function useTema() {
  const contexto = useContext(TemaContext);

  if (!contexto) {
    throw new Error('useTema tiene que usarse adentro de TemaContext.Provider');
  }

  return contexto; // { tema, cambiarTema }
}
BotonTema.jsx
import { useTema } from './useTema';

function BotonTema() {
  const { tema, cambiarTema } = useTema();

  return (
    <button onClick={cambiarTema}>
      Tema actual: {tema}
    </button>
  );
}

Cualquier componente que necesite el tema usa useTema() en vez de repetir useContext(TemaContext) y su validación en todos lados. Esto es exactamente lo mismo que exportar e importar funciones de la Clase 1 de Modularización, aplicado a hooks.

!
Reglas de los hooks Los hooks (useState, useEffect, useRef, hooks propios, etc.) solo se llaman en el nivel superior de un componente o de otro hook. Nunca adentro de un if, un for, ni de una función anidada o un return anticipado. React depende de que se llamen siempre en el mismo orden, en cada render, para saber a qué estado corresponde cada uno; romper esa regla produce bugs difíciles de rastrear.

✎Ejercicio

  1. Crear un TemaContext.js con un Provider que guarde tema ('claro' o 'oscuro') usando useState, y una función para alternarlo.
  2. Armar un custom hook useTema.js que envuelva el useContext.
  3. Usar ese hook en 2 componentes distintos (por ejemplo, un Header y un Boton) para confirmar que ambos ven el mismo tema sin pasarse props entre sí.

TemaContext.js
import { createContext, useState } from 'react';

export const TemaContext = createContext(null);

export function TemaProvider({ children }) {
  const [tema, setTema] = useState('claro');

  function cambiarTema() {
    setTema(anterior => (anterior === 'claro' ? 'oscuro' : 'claro'));
  }

  return (
    <TemaContext.Provider value={{ tema, cambiarTema }}>
      {children}
    </TemaContext.Provider>
  );
}
useTema.js
import { useContext } from 'react';
import { TemaContext } from './TemaContext';

export function useTema() {
  return useContext(TemaContext);
}
Header.jsx
import { useTema } from './useTema';

export default function Header() {
  const { tema } = useTema();
  return <header className={tema}>Mi sitio ({tema})</header>;
}
Boton.jsx
import { useTema } from './useTema';

export default function Boton() {
  const { tema, cambiarTema } = useTema();
  return <button onClick={cambiarTema}>Cambiar a {tema === 'claro' ? 'oscuro' : 'claro'}</button>;
}
App.jsx
import { TemaProvider } from './TemaContext';
import Header from './Header';
import Boton from './Boton';

function App() {
  return (
    <TemaProvider>
      <Header />
      <Boton />
    </TemaProvider>
  );
}

export default App;
Para remarcar en clase Header y Boton son hermanos, ninguno le pasa nada al otro, y sin embargo los dos ven el mismo tema y quedan sincronizados: si uno lo cambia, el otro se actualiza solo.
