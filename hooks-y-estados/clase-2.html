useEffect

Cómo hacer que un componente hable con el mundo exterior, y traer datos de una API

1Qué es un efecto secundario

Hasta ahora, un componente solo hacía una cosa: recibir props/estado y devolver JSX. Eso es renderizar, y React espera que sea un proceso predecible y sin sorpresas.

Pero muchas veces un componente necesita hacer algo que sale de ese mundo: pedir datos a un servidor, iniciar un timer, escuchar un evento del navegador. A eso se le llama efecto secundario, y para eso existe useEffect.

Idea central Renderizar es calcular qué mostrar. Un efecto es todo lo demás: algo que pasa "al costado" del render, generalmente para comunicarse con algo externo a React.

2Sintaxis básica

Ejemplo mínimo
import { useEffect } from 'react';

useEffect(() => {
  console.log('el componente se dibujó en pantalla');
});

useEffect recibe una función. React la ejecuta después de que el componente se dibuja en pantalla, no durante el render.

3El array de dependencias

Solo con eso, el efecto se ejecutaría después de cada render, lo cual casi nunca es lo que se quiere. El segundo argumento de useEffect controla cuándo se vuelve a ejecutar:

Segundo argumento Cuándo se ejecuta el efecto
sin segundo argumento después de cada render
[] (array vacío) una sola vez, cuando el componente aparece en pantalla
[valor] cuando cambia ese valor (además de la primera vez) 
useEffect(() => {
  console.log('se ejecuta una sola vez');
}, []);

useEffect(() => {
  console.log('se ejecuta cuando cambia usuarioId');
}, [usuarioId]);

4La función de limpieza

Si un efecto arma algo que después hay que desarmar (un timer, un event listener), useEffect puede devolver una función de limpieza, que React ejecuta antes de correr el efecto de nuevo, o cuando el componente desaparece de pantalla:

Reloj.jsx
useEffect(() => {
  const id = setInterval(() => {
    console.log('tick');
  }, 1000);

  return () => clearInterval(id); // limpieza
}, []);

Sin esa limpieza, el timer seguiría corriendo aunque el componente ya no esté en pantalla, generando comportamientos raros y fugas de memoria, que pueden llegar a afectar mucho el rendimiento.

5Caso de uso real: traer datos de una API

El uso más común de useEffect es pedir datos apenas se muestra el componente. Se combina con useState, de la clase anterior, para guardar los datos, y con conditional rendering para mostrar distintos estados: cargando, error, o los datos ya listos.

ListaUsuarios.jsx
import { useState, useEffect } from 'react';

function ListaUsuarios() {
  const [usuarios, setUsuarios] = useState([]);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('https://api.ejemplo.com/usuarios')
      .then(respuesta => respuesta.json())
      .then(datos => {
        setUsuarios(datos);
        setCargando(false);
      })
      .catch(err => {
        setError(err.message);
        setCargando(false);
      });
  }, []); // [] = solo al montar el componente

  if (cargando) return <p>Cargando...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {usuarios.map(u => <li key={u.id}>{u.nombre}</li>)}
    </ul>
  );
}

export default ListaUsuarios;
Para remarcar en clase Los tres if de arriba son el mismo conditional rendering de la Clase 1, aplicado a un caso real: mientras cargando es true, no tiene sentido intentar mostrar usuarios.

✎Ejercicio

  1. Crear un componente Clima.jsx que, al montarse, haga un fetch (podés usar la API de clima de la revista del semestre pasado o simular una API usando setTimeout) y muestre "Cargando..." mientras espera.
  2. Cuando lleguen los datos, mostrarlos. Si falla, mostrar un mensaje de error.
  3. Bonus: agregar un useEffect separado que solo loguee en consola cada vez que cambien los datos del clima (usando el array de dependencias).

Clima.jsx
import { useState, useEffect } from 'react';

export default function Clima() {
  const [datos, setDatos] = useState(null);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDatos({ temperatura: 22, ciudad: 'Montevideo' });
      setCargando(false);
    }, 1500);

    return () => clearTimeout(timer);
  }, []);

  useEffect(() => {
    if (datos) {
      console.log('los datos del clima cambiaron:', datos);
    }
  }, [datos]);

  if (cargando) return <p>Cargando...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <p>{datos.ciudad}: {datos.temperatura}&deg;C</p>
  );
}
Para remarcar en clase Son dos useEffect distintos, con responsabilidades distintas. Uno pide los datos una sola vez ([]), el otro reacciona cada vez que datos cambia ([datos]). No hay problema en tener varios useEffect en el mismo componente.
