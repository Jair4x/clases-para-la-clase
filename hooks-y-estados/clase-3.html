useRef

Cuándo guardar un valor sin que dispare un re-render, y cómo tocar el DOM directamente

1El problema: no todo necesita re-renderizar

useState es para datos que, al cambiar, tienen que actualizar lo que se ve en pantalla. Pero a veces se necesita guardar un valor que persista entre renders, sin que ese cambio dispare un re-render. Por ejemplo, contar cuántas veces se ejecutó algo, o guardar el id de un setInterval para poder cancelarlo después.

si se usara useState para esto, sobrarían renders
const [idTimer, setIdTimer] = useState(null);
// cada setIdTimer(...) volvería a renderizar el componente,
// aunque a nadie le importe ese valor en la pantalla

2La solución: useRef

useRef es un hook que le da a un componente un "casillero" propio para guardar un valor, que persiste entre renders igual que el estado, pero con una diferencia clave: cambiarlo no le pide nada a React. No dispara un re-render, no hace que el componente se vuelva a ejecutar, simplemente el valor queda actualizado ahí, disponible para la próxima vez que el componente corra.

Es la herramienta indicada para datos que el componente necesita recordar "para uso interno", pero que no forman parte de lo que se ve en pantalla.

Ejemplo mínimo
import { useRef } from 'react';

const contadorRef = useRef(0);

console.log(contadorRef.current); // 0

contadorRef.current = contadorRef.current + 1;
console.log(contadorRef.current); // 1, sin re-render

Desglosando esa sintaxis, parte por parte:

  • useRef(0): el argumento (0 acá) es el valor inicial, igual que el argumento de useState.
  • A diferencia de useState, no devuelve un array para destructurar. Devuelve directamente un objeto, siempre con la misma forma: { current: valor }.
  • contadorRef es ese objeto. Es el mismo objeto en todos los renders del componente, React nunca lo reemplaza por otro.
  • .current es la única propiedad de ese objeto, y ahí vive el valor real. Se lee y se escribe directamente: contadorRef.current, sin funciones de por medio como el setCuenta de useState.
useState useRef
Al cambiar el valor dispara un re-render no dispara nada
Se lee/escribe con la variable y su setter .current
Se usa para datos que afectan lo que se ve valores "internos", o referencias al DOM

3Caso de uso 1: guardar un valor mutable

Reloj.jsx
import { useRef, useEffect } from 'react';

function Reloj() {
  const idTimer = useRef(null);

  useEffect(() => {
    idTimer.current = setInterval(() => {
      console.log('tick');
    }, 1000);

    return () => clearInterval(idTimer.current);
  }, []);

  return <p>Mirá la consola</p>;
}

Acá idTimer guarda el identificador del timer entre renders, para poder limpiarlo después. A nadie le importa mostrar ese id en pantalla, por eso no es useState.

4Caso de uso 2: referenciar un elemento del DOM

El otro uso muy común de useRef es obtener acceso directo a un elemento del HTML, para hacer algo que React no maneja por props (como enfocar un input).

FormularioLogin.jsx
import { useRef, useEffect } from 'react';

function FormularioLogin() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus(); // apenas aparece, el cursor ya está ahí
  }, []);

  return <input ref={inputRef} placeholder="Usuario" />;
}

Cuando se pasa un ref como el atributo ref de una etiqueta HTML, React hace que inputRef.current apunte al elemento real del DOM, con todos sus métodos nativos (.focus(), .scrollIntoView(), etc).

Idea central Si el valor tiene que aparecer en pantalla → useState. Si es un dato interno que solo el componente necesita recordar, o una referencia a un elemento del DOM → useRef.

CampoConFoco.jsx
import { useRef, useEffect } from 'react';

export default function CampoConFoco() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus();
  }, []);

  return <input ref={inputRef} placeholder="Escribí acá" />;
}
ContadorDeRenders.jsx
import { useState, useRef } from 'react';

export default function ContadorDeRenders() {
  const [texto, setTexto] = useState('hola');
  const renders = useRef(0);

  renders.current = renders.current + 1;
  console.log('este componente se renderizó', renders.current, 'veces');

  return (
    <div>
      <p>{texto}</p>
      <button onClick={() => setTexto('chau')}>Cambiar texto</button>
    </div>
  );
}
Para remarcar en clase Incrementar renders.current directamente en el cuerpo del componente (no en un efecto) funciona porque ese incremento no necesita disparar nada; simplemente cuenta cuántas veces pasó por ahí la función.
