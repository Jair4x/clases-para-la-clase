Estado y useState

Cómo un componente recuerda cosas entre renders, y cómo mostrar interfaz distinta según ese estado

1Qué es un render

Antes de hablar de estado, una definición corta: un render es el momento en el que React ejecuta la función de un componente y calcula qué JSX tiene que mostrar en pantalla.

Cada vez que un componente aparece por primera vez, React lo renderiza. Y cada vez que algo le indica a React "esto puede haber cambiado", React lo vuelve a renderizar: ejecuta la función de nuevo, de punta a punta, y compara el resultado con lo que había en pantalla para actualizar solo lo necesario.

2El problema: una variable no alcanza

Entonces, ¿por qué no usar una variable común para guardar datos que cambian?

Contador.jsx (no funciona como uno esperaría)
function Contador() {
  let cuenta = 0;

  function incrementar() {
    cuenta = cuenta + 1;
    console.log(cuenta); // esto sí cambia
  }

  return (
    <div>
      <p>Cuenta: {cuenta}</p>
      <button onClick={incrementar}>+1</button>
    </div>
  );
}

El valor de cuenta cambia en la consola, pero la pantalla nunca se actualiza. Nada en ese código le pide a React que vuelva a renderizar, así que la función Contador no se vuelve a ejecutar, y ese <p> se queda con el JSX del primer render, con cuenta en 0 para siempre.

Idea central Modificar una variable no provoca un render. Hace falta algo que React reconozca como una señal de "volvé a renderizar este componente". Para eso existe el estado.

3useState: declarar estado

El estado de un componente es un valor que React guarda por fuera de la función, asociado a esa instancia del componente. A diferencia de una variable común, cuando el estado se actualiza con la herramienta correcta, React se entera y dispara un nuevo render con el valor actualizado.

Contador.jsx
import { useState } from 'react';

function Contador() {
  const [cuenta, setCuenta] = useState(0);

  return (
    <div>
      <p>Cuenta: {cuenta}</p>
      <button onClick={() => setCuenta(cuenta + 1)}>+1</button>
    </div>
  );
}

useState(0) devuelve un array de dos elementos: el valor actual del estado (cuenta), y una función para pedirle a React que lo actualice (setCuenta). 0 es el valor con el que arranca la primera vez.

Por qué se definen con paréntesis rectas

Ya vimos cómo des-estructurar (destructuring) props en una de las clases del tema anterior, sacando propiedades de un objeto por nombre: { nombre } = props. Sin embargo, acá, en lugar de hacer referencia al nombre que queremos extraer, lo hacemos a la posición: useState no devuelve un objeto, devuelve un array, y de un array se destructura por posición:

// destructuring de array, plano, sin React
const par = ['Ana', 30];
const [nombre, edad] = par;
// nombre = 'Ana' (primer elemento), edad = 30 (segundo elemento)

Con useState pasa exactamente eso: el primer elemento del array (el valor) va a la primera variable, el segundo (la función para actualizar) va a la segunda. Por eso el nombre cuenta y setCuenta lo eligen ustedes, no viene fijo por ningún lado.

4Actualizar el estado

El estado nunca se modifica directamente. Esto no funciona:

cuenta = cuenta + 1; // no dispara un render, es el mismo problema de la sección 2

Siempre se usa la función que devuelve useState, que es la única forma que tiene React de enterarse del cambio:

setCuenta(5);              // fija el valor en 5
setCuenta(cuenta + 1);    // lo calcula a partir del valor actual

La segunda forma, setCuenta(cuenta + 1), tiene un problema cuando la función que la llama fue creada en un render anterior y "quedó viva" para más adelante. Un caso práctico y común: un contador que suma 1 solo, automáticamente, cada un segundo.

Aviso El siguiente ejemplo usa useEffect, que vemos recién en la próxima clase. Por ahora alcanza con saber que ese código arranca un temporizador que llama a setCuenta una vez por segundo.
esto se queda pegado en 1, nunca llega a 2, 3, 4...
useEffect(() => {
  const id = setInterval(() => {
    setCuenta(cuenta + 1);
  }, 1000);

  return () => clearInterval(id);
}, []);

La función que corre cada segundo se creó una sola vez, cuando el efecto se ejecutó por primera vez. En ese momento, quedó "atada" al valor de cuenta que existía en ese instante (por ejemplo, 0). Entonces cada segundo hace 0 + 1, siempre, sin enterarse de que el estado ya cambió a 1, después a 2, etc.

Para evitarlo, en vez de pasarle un valor calculado a mano, se le pasa una función. React le va a ir pasando a esa función el valor más actualizado disponible en ese momento, sin importar cuándo se creó la función que la está llamando:

esto sí funciona, cuenta 1, 2, 3, 4...
useEffect(() => {
  const id = setInterval(() => {
    setCuenta(anterior => anterior + 1);
  }, 1000);

  return () => clearInterval(id);
}, []);

Acá, cada segundo, la función le pide a React "dame el valor más actualizado que tengas, y sumale 1", en vez de arrastrar un valor viejo capturado en el pasado. Como regla práctica: si una actualización de estado puede llegar a ejecutarse fuera del render que la originó (en un timer, una respuesta de red, un evento async), mejor usar la forma con función.

5Qué pasa cuando el estado cambia

Al llamar a setCuenta, pasan tres cosas, en orden:

  1. React guarda el nuevo valor.
  2. React vuelve a ejecutar la función del componente (un re-render, la idea de la sección 1), con el nuevo valor de cuenta.
  3. React actualiza en pantalla solo lo que efectivamente cambió, no la página entera.
Dato Cada componente tiene su propio estado, aislado del resto. Si ponés dos <Contador /> en pantalla, cada uno lleva su propia cuenta, aunque estén hechos con el mismo código.

6Conditional rendering

Ahora que un componente puede tener estado, es común mostrar cosas distintas según ese estado. A eso se le llama renderizado condicional. Tres formas comunes:

Operador ternario

Es una forma corta de escribir un if/else que devuelve un valor, en vez de ejecutar bloques de código. La sintaxis es siempre la misma: condición ? valorSiVerdadero : valorSiFalso. Sin nada de React todavía:

const edad = 20;
const mensaje = edad >= 18 ? 'Mayor de edad' : 'Menor de edad';
// mensaje = 'Mayor de edad'

Adentro del JSX funciona exactamente igual, solo que en vez de un string, lo que se devuelve a cada lado es otro JSX:

dentro del JSX
{estaConectado ? <p>Bienvenido</p> : <p>Iniciá sesión</p>}

Operador &&, para mostrar u ocultar

&& en JavaScript no da como resultado true o false: evalúa de izquierda a derecha, y si el primer valor es falso, ni siquiera mira el segundo y devuelve ese primer valor tal cual. Si el primer valor es verdadero, devuelve directamente el segundo valor. Sin React:

console.log(false && 'hola'); // false (ni siquiera llega a mirar 'hola')
console.log(true && 'hola');  // 'hola' (el primero era verdadero, devuelve el segundo)

React, al renderizar, simplemente no dibuja nada cuando el valor a mostrar es false (tampoco si es null o undefined). Por eso esta combinación funciona como un "mostrar u ocultar":

dentro del JSX
{hayErrores && <p className="error">Revisá el formulario</p>}

Si hayErrores es false, toda la expresión da false y React no dibuja nada. Si es true, la expresión da el <p> de la derecha, y eso es lo que se dibuja.

if / else antes del return, para casos más grandes

Perfil.jsx
function Perfil({ cargando }) {
  if (cargando) {
    return <p>Cargando...</p>;
  }

  return <p>Perfil listo</p>;
}
Forma Cuándo usarla
Ternario ? : Elegir entre dos cosas para mostrar
Operador && Mostrar algo, u ocultarlo del todo
if / else Lógica más larga, o retornos muy distintos entre sí

Contador.jsx
import { useState } from 'react';

export default function Contador() {
  const [cuenta, setCuenta] = useState(0);

  return (
    <div>
      <p>Cuenta: {cuenta}</p>

      {cuenta < 0 && <p>negativo</p>}
      {cuenta > 0 && <p>positivo</p>}

      <button onClick={() => setCuenta(anterior => anterior + 1)}>+1</button>
      <button onClick={() => setCuenta(anterior => anterior - 1)}>-1</button>
      <button onClick={() => setCuenta(0)}>Reiniciar</button>
    </div>
  );
}
Interruptor.jsx
import { useState } from 'react';

export default function Interruptor() {
  const [visible, setVisible] = useState(false);

  return (
    <div>
      <button onClick={() => setVisible(anterior => !anterior)}>
        {visible ? 'Ocultar' : 'Mostrar'}
      </button>

      {visible && <p>Acá está el texto que aparece y desaparece.</p>}
    </div>
  );
}
Para remarcar en clase En Contador usamos setCuenta(anterior => anterior + 1) en vez de setCuenta(cuenta + 1), justamente porque el nuevo valor depende del anterior.
