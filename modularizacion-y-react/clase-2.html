Componentes

Por qué existen, cuándo conviene hacerlos y cómo funcionan

1La idea central

Un componente de React es, en el fondo, una función de JavaScript que devuelve HTML (en realidad JSX, algo muy parecido a HTML, que compila a JS puro).

Saludo.jsx
function Saludo() {
  return <h1>Hola, mundo!</h1>;
}

Se usa como si fuera una etiqueta HTML propia:

<Saludo />

Esto conecta directo con lo que ya saben de JavaScript: es una función normal, solo que en vez de devolver un número o un string, devuelve interfaz.

2Por qué hacer componentes

Sin componentizar, una pantalla completa sería un solo bloque gigante de JSX. Los problemas son los mismos que vimos con los módulos en la Clase 1, aplicados ahora a la interfaz:

  • Reutilización: si tenés el mismo botón en 5 lugares, lo escribís una sola vez.
  • Mantenibilidad: si hay que cambiar el diseño de una tarjeta, se cambia en un solo lugar.
  • Legibilidad: <Header /><Sidebar /><Contenido /> se lee mejor que 200 líneas de <div> anidados.
  • Testing: podés probar una pieza chica de forma aislada.

3Cuándo conviene hacer un componente

Reglas prácticas:

  • Se repite visualmente en más de un lugar → componente.
  • Tiene su propia lógica (estado, cálculos, validaciones) → componente aparte.
  • Es una unidad conceptual clara (un card, un botón, un formulario, un ítem de lista) → componente.
  • Si un componente crece demasiado (muchas responsabilidades mezcladas) → dividirlo en componentes más chicos.
Aclaración No hay que exagerar desde el día 1. No todo necesita ser su propio componente de entrada; se refactoriza cuando algo empieza a repetirse o a complicarse.

4Cómo se conecta con la Clase 1

Cada componente normalmente vive en su propio archivo, y se exporta/importa igual que cualquier función:

Boton.jsx
export default function Boton() {
  return <button>Click acá</button>;
}
App.jsx
import Boton from './Boton';

function App() {
  return (
    <div>
      <h1>Mi app</h1>
      <Boton />
    </div>
  );
}

export default App;

Es literalmente lo mismo que en la Clase 1: un archivo exporta algo, otro lo importa. La única diferencia es que lo que se exporta es una función que devuelve interfaz.

5Composición: componentes dentro de componentes

Card.jsx
function Card() {
  return (
    <div className="card">
      <Boton />
    </div>
  );
}

Los componentes se combinan (se "componen") entre sí, como piezas de Lego.

  3. Crear un componente Card.jsx y usarlo 3 veces dentro de App con contenido repetido, para sentir el valor de reutilizar.

Header.jsx
export default function Header() {
  return (
    <header>
      <h1>Mi tienda</h1>
      <p>Productos frescos todos los días</p>
    </header>
  );
}
Footer.jsx
export default function Footer() {
  return (
    <footer>
      <p>&copy; 2026 Mi tienda</p>
    </footer>
  );
}
Card.jsx
export default function Card() {
  return (
    <div className="card">
      <h3>Producto</h3>
      <p>Descripción genérica del producto</p>
    </div>
  );
}
App.jsx
import Header from './Header';
import Footer from './Footer';
import Card from './Card';

function App() {
  return (
    <div>
      <Header />
      <Card />
      <Card />
      <Card />
      <Footer />
    </div>
  );
}

export default App;
