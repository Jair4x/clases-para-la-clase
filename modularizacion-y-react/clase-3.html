Props

Cómo pasar datos a un componente, comparado con funciones normales de JS

1El problema

En la Clase 2, Card siempre muestra lo mismo. ¿Cómo hacemos que cada Card muestre contenido distinto sin duplicar el componente?

2Comparación con funciones de JS normales

Esto es lo más importante de la clase, porque conecta con algo que ya dominan.

función normal de JS
function saludar(nombre) {
  return `Hola, ${nombre}`;
}

saludar('Juan');   // "Hola, Juan"
saludar('María');  // "Hola, María"
componente de React
function Saludo({ nombre }) {
  return <h1>Hola, {nombre}</h1>;
}
<Saludo nombre="Juan" />
<Saludo nombre="María" />

Las props son, ni más ni menos, los parámetros de la función-componente. Lo que cambia es la sintaxis:

  • En una función normal, los parámetros se pasan entre paréntesis: saludar('Juan').
  • En un componente, se pasan como si fueran atributos HTML: <Saludo nombre="Juan" />.
  • React junta todos esos "atributos" en un solo objeto, que por convención se llama props.
sin destructuring
function Saludo(props) {
  return <h1>Hola, {props.nombre}</h1>;
}

Es exactamente lo mismo que la versión de arriba, con la diferencia de que ahí usamos destructuring. Si esa palabra no les suena, vale la pena una pausa antes de seguir.

Repaso rápido: destructuring en JS puro

Destructuring es una forma corta de sacar valores de adentro de un objeto, sin tener que escribir objeto.propiedad cada vez. No tiene nada de React todavía, es JavaScript común:

forma larga
const persona = { nombre: 'Ana', edad: 30 };

const nombre = persona.nombre;
const edad = persona.edad;

console.log(nombre); // 'Ana'
console.log(edad);   // 30
misma idea, con destructuring
const persona = { nombre: 'Ana', edad: 30 };

const { nombre, edad } = persona;

console.log(nombre); // 'Ana'
console.log(edad);   // 30

Las llaves { nombre, edad } le dicen a JavaScript: "de este objeto, sacame estas dos propiedades y creame una variable para cada una, con el mismo nombre". Es exactamente lo mismo que las dos líneas de la forma larga, solo que en una sola línea.

Dato El nombre de la variable tiene que coincidir con el nombre de la propiedad. Si el objeto tiene nombre, la variable se tiene que llamar nombre; no es un orden posicional como con los arrays.

Ahora sí: en React, props es un objeto (como persona en el ejemplo), así que el destructuring funciona exactamente igual, solo que se escribe directo en los parámetros de la función:

con destructuring
function Saludo({ nombre }) {
  return <h1>Hola, {nombre}</h1>;
}

Solo que la segunda versión usa destructuring (que ya conocen de JS puro) para no escribir props.nombre todo el tiempo.

3Varias props

Card.jsx
function Card({ titulo, descripcion, imagen }) {
  return (
    <div className="card">
      <img src={imagen} alt={titulo} />
      <h2>{titulo}</h2>
      <p>{descripcion}</p>
    </div>
  );
}
<Card
  titulo="Producto A"
  descripcion="Descripción del producto A"
  imagen="/img/a.png"
/>
<Card
  titulo="Producto B"
  descripcion="Descripción del producto B"
  imagen="/img/b.png"
/>

4Props son de solo lectura

Un componente no puede modificar sus propias props, de la misma forma que una función normal no debería modificar los parámetros que recibe. Si algo necesita cambiar con el tiempo (como resultado de una interacción), eso ya es un tema de estado (useState), que queda para otra clase, pero vale la pena mencionarlo para que no se confundan.

5Children: un tipo especial de prop

Contenedor.jsx
function Contenedor({ children }) {
  return <div className="contenedor">{children}</div>;
}
<Contenedor>
  <p>Este contenido se pasa "adentro" del componente</p>
</Contenedor>

children es una prop implícita que representa todo lo que se pone entre las etiquetas de apertura y cierre del componente.

6Cuándo usar props

  • Cuando un componente necesita datos externos para renderizar (texto, número, url, etc.).
  • Cuando querés que un componente sea reutilizable con distinto contenido.
  • Cuando un componente padre necesita pasarle una función a un hijo (por ejemplo, qué hacer al hacer click), ya que las funciones son valores como cualquier otro en JS.
Idea central Props = parámetros de función. Mismo concepto que ya conocen, solo que se pasan con sintaxis de atributos y llegan agrupados en un objeto.

Espacio online de pruebas

Se abre un proyecto de React nuevo y vacío en CodeSandbox (react.new). Pegá ahí el código de arriba o el de la solución para jugar con él, sin instalar nada.

Ver soluciónClick para expandir
Card.jsx
export default function Card({ titulo, descripcion, imagen, onClick }) {
  return (
    <div className="card" onClick={onClick}>
      <img src={imagen} alt={titulo} />
      <h3>{titulo}</h3>
      <p>{descripcion}</p>
    </div>
  );
}
App.jsx
import Card from './Card';

function App() {
  return (
    <div>
      <Card
        titulo="Producto A"
        descripcion="El más pedido"
        imagen="/img/a.png"
        onClick={() => alert('Clickeaste A')}
      />
      <Card
        titulo="Producto B"
        descripcion="Edición limitada"
        imagen="/img/b.png"
        onClick={() => alert('Clickeaste B')}
      />
      <Card
        titulo="Producto C"
        descripcion="Recién llegado"
        imagen="/img/c.png"
        onClick={() => alert('Clickeaste C')}
      />
    </div>
  );
}

export default App;
Para remarcar en clase El bonus muestra que una prop no tiene por qué ser un dato: acá onClick es una función distinta en cada tarjeta, pasada de la misma forma que titulo o imagen.
