Import / Export

Qué es un módulo, y cómo importar y exportar código propio

1Qué es un módulo

Antes de hablar de modularizar, conviene tener claro qué es un módulo.

Un módulo es un archivo de código con su propio espacio aislado, que decide explícitamente qué partes de sí mismo comparte con otros archivos. Todo lo que no comparte queda "adentro", invisible desde afuera.

Pensarlo como una caja cerrada: adentro puede haber muchas variables y funciones, pero desde afuera solo se ve lo que la caja decide mostrar.

Dato Ya usaron módulos, aunque no los hayan escrito ustedes. Cada librería de Node que instalaron con npm es un módulo: alguien escribió el código, decidió qué partes exponer, y lo empaquetó para que otros lo usen.

2Lo que ya conocen: importar

Hasta ahora usaron módulos desde el lado de "consumirlos". Algo así les resulta familiar:

index.js
const express = require('express');

const app = express();

Acá express es un módulo. Pero hasta este punto solo vieron un lado de la historia: siempre importaron, nunca exportaron nada propio. Falta la otra mitad.

3El otro lado: exportar

Para que express se pueda importar, alguien tuvo que escribir, en algún archivo de esa librería, algo parecido a esto:

adentro de la librería express (simplificado)
module.exports = crearAplicacion;

Eso es exportar: decidir qué parte del archivo va a estar disponible para quien lo importe. Vamos a escribir nuestro propio módulo, de punta a punta.

matematicas.js
function sumar(a, b) {
  return a + b;
}

module.exports = { sumar };
index.js
const { sumar } = require('./matematicas');
console.log(sumar(2, 3));

Esto es CommonJS, el sistema de módulos "clásico" de Node: module.exports para exportar, require para importar.

4Por qué modularizar

¿Qué pasa si todo el código de una app está en un solo archivo?

  • Difícil de leer y mantener
  • Difícil de reutilizar código
  • Difícil de trabajar en equipo (todos tocan el mismo archivo, y eso genera conflictos)
  • Difícil de testear partes aisladas
Idea central Modularizar es dividir el código en piezas pequeñas, cada una con una responsabilidad, que se combinan importándolas entre sí. Exportar es cómo una pieza decide qué comparte, importar es cómo otra pieza la usa.

5ES Modules, lo que usa React

React usa ES Modules (import / export), no CommonJS. La sintaxis cambia, pero la idea es la misma: exportar algo desde un archivo, importarlo en otro.

matematicas.js
export function sumar(a, b) {
  return a + b;
}

export function restar(a, b) {
  return a - b;
}
index.js
import { sumar, restar } from './matematicas';

console.log(sumar(2, 3));
console.log(restar(5, 1));

Esto se llama named export: se puede exportar varias cosas del mismo archivo, y al importar se usa el mismo nombre entre llaves.

6Export default

También existe el export default, para cuando un archivo exporta "una cosa principal":

saludo.js
export default function saludo(nombre) {
  return `Hola, ${nombre}`;
}
index.js
import saludo from './saludo'; // sin llaves, y con cualquier nombre

console.log(saludo('Ana'));
Named export Default export
Cantidad por archivo Varios Uno solo
Al importar { nombre exacto } cualquier nombre
Uso típico en React funciones utilitarias, hooks, constantes el componente principal del archivo

7CommonJS vs ES Modules

// CommonJS (Node clásico)
module.exports = algo;
const algo = require('./archivo');

// ES Modules (React / JS moderno)
export default algo;
import algo from './archivo';

  1. Crear un archivo utilidades.js con 3 funciones (ej: formatearFecha, esPar, capitalizar) usando named exports.
  2. Crear un archivo main.js que las importe y las use.
  3. Bonus: convertir una de esas funciones a export default en otro archivo y notar la diferencia al importarla.
Espacio online de pruebas

Se abre un proyecto de React nuevo y vacío en CodeSandbox (react.new). Pegá ahí el código de arriba o el de la solución para jugar con él, sin instalar nada.

Ver soluciónClick para expandir
utilidades.js
export function formatearFecha(fecha) {
  return fecha.toLocaleDateString('es-AR');
}

export function esPar(numero) {
  return numero % 2 === 0;
}

export function capitalizar(texto) {
  return texto.charAt(0).toUpperCase() + texto.slice(1);
}
main.js
import { formatearFecha, esPar, capitalizar } from './utilidades';

console.log(formatearFecha(new Date()));  // ej: 18/8/2026
console.log(esPar(4));                    // true
console.log(capitalizar('hola'));       // Hola

Bonus: una de las funciones como default export

capitalizar.js
export default function capitalizar(texto) {
  return texto.charAt(0).toUpperCase() + texto.slice(1);
}
main.js
import capitalizarPalabra from './capitalizar'; // cualquier nombre, sin llaves

console.log(capitalizarPalabra('mundo')); // Mundo
Para remarcar en clase La diferencia clave del bonus no es el resultado, es la importación: sin llaves y con el nombre que cada uno elija, porque el archivo exporta una sola cosa por default.
